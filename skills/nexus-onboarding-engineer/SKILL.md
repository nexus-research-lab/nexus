# 研发新手引导

用真实对话完成两个里程碑：创建研发 Agent；创建一个 Bug 排查或技术评审 Room 并进入协作。不要把自然语言做成固定指令映射。

开始收集信息前必须加载 `nexus-onboarding-card-kit`。Agent 名称、职责、风格、创建确认、Room 任务、成员确认和 Room 创建确认必须依次调用预置卡片；禁止用普通文本问题代替。名称候选使用“代码搭档”“故障猎手”“架构哨兵”，职责候选使用“功能研发与实现”“Bug 定位与修复”“架构设计与评审”，风格候选使用“严谨排查”“工程实践”“架构演进”。Room 任务候选使用“线上 Bug 排查”“技术方案评审”“性能与稳定性诊断”。卡片超时后保留当前步骤，不得降级为文本追问。

启动消息会声明这是一次全新的旅程。只用当前会话中的卡片答案和创建结果恢复进度；查询真实 Agent 和 Room 只能校验资源，历史资源不得自动算作本次已完成或导致跳过卡片。通过预置卡片逐步收集 Agent 名称、技术职责、常见输入与期望产出。加载 `nexus-manager` 后，在用户通过 `新手引导 · 创建 Agent` 卡片确认后用 `nexusctl --json agent create` 真实创建，并通过 `--vibe-tag` 写入风格标签。

第二个任务通过 `新手引导 · Room 任务` 卡片收集真实 Bug、故障或技术方案，建议由用户的研发 Agent、复现与测试顾问、架构评审顾问协作。通过成员与最终确认卡片后复用已有 Agent、创建缺失成员。创建 Room 时必须从 `agent list` 找到 `is_main=true` 的 Nexus 主页 Agent，把它连同三位协作 Agent 加入成员并用主持人三项参数设为主持人；`--initial-message` 携带真实问题、复现/测试和架构评审分工的预置开场（换行用字面量 `\n`），重复 `--initial-target-agent-id` 只定向两位顾问。创建“Bug 排查战情室”或语义更合适的 Room。创建成功必须由卡片套件的模板 H 收口：保留真实 `room create` 结果供 Nexus 渲染预定义可点击卡片，不要追加查询命令补卡片，也不要手写假卡片。进入 Room 后由 Nexus 主持人自动发出开场，后续输出由 Room 真实模型服务完成；此时才完成引导。

每轮只推进一个步骤；缺信息就问；失败就反馈真实错误；用户临时询问系统操作时先回答再回到里程碑。
