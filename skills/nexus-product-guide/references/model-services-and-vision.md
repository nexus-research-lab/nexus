# 模型服务与模型能力

这份资料说明“设置”里的供应商、默认模型和模型能力操作路径。回答用户的模型或图片问题时，优先使用界面上的名称。

## 模型服务在哪里

入口是 **设置 → 供应商**。页面标题为“模型供应商”，负责：

- 添加、启用或停用模型服务；
- 填写服务地址和凭证，并测试连接；
- 同步或手动添加模型；
- 查看模型的能力标记和可用状态。

“连接测试成功”只说明当前连接测试通过，不代表该服务下的每个模型都支持聊天、工具或视觉理解。

## 默认模型在哪里

入口是 **设置 → 默认模型**。这里分别设置：

- 默认对话模型；
- 默认生图模型；
- **视觉理解模型**；
- 后台任务模型。

“视觉理解模型”的说明是：主模型无法查看图片、又需要视觉细节时，系统才调用这里选择的模型。已选的供应商或模型如果失效，先回到“设置 → 供应商”检查状态和能力，再重新选择；不要按同名模型自动替换。

## 默认模型的四类用途

- **默认对话模型**：没有为 Agent 单独指定模型时，用于普通聊天、任务执行和工具调用。
- **默认生图模型**：图片生成没有指定模型服务时使用；能生图不代表能理解用户图片。
- **视觉理解模型**：主模型无法查看图片、又需要视觉细节时按需调用；它不是每条消息都会使用。
- **后台任务模型**：标题生成、摘要等后台任务优先使用；不会自动替代当前会话的对话模型。

智能体和当前会话可以有自己的模型选择。遇到“明明改了默认模型但当前聊天没变化”，先检查智能体和当前会话的明确选择。

## 模型能力标记

模型能力以当前精确的“供应商 + 模型”记录为准。不同供应商的 Coding Plan、按量 API 和兼容服务可能提供不同的模型清单；同一个模型名称也不能证明不同服务拥有相同能力。

- **视觉理解**表示模型可以接收并理解图片输入。
- **文本对话**表示模型可以返回普通文本回答，是普通聊天的基础能力。
- **工具调用**表示模型可以按产品协议调用工具；连接测试成功不等于每个模型都支持工具。
- **推理**表示目录或测试确认模型提供独立的推理能力，不等于回答一定更准确。
- **图片输出**表示模型可以生成图片，不能推断它可以理解用户图片。
- **图片编辑**表示当前模型和接入方式支持图片编辑；有图片输入或图片输出单项能力都不能推断支持编辑。
- **向量表示**表示模型用于向量化或检索，不是普通对话模型。
- 视觉 MCP 或图片工具可用，也不能代替模型本身的视觉理解能力。
- 模型目录没有视觉能力标记时，不要向用户承诺它能看图。

“自动识别”表示 Nexus 根据当前供应商、模型目录和已完成的能力测试给出结果，不是根据模型名称猜测。能力未知时，不要把未知说成支持或不支持；可以引导用户查看模型行的能力标记或运行测试。

## 按能力排查模型问题

先确认用户问的是哪一类能力，再到 **设置 → 供应商** 查看对应模型行的能力标记或测试结果：

- 普通聊天不可用：检查“文本对话”和供应商连接状态。
- 工具调用失败：检查“工具调用”能力、当前运行环境和会话权限。
- 图片无法理解：检查“视觉理解”，再按下面的视觉步骤处理。
- 图片生成失败：检查“图片输出”和“默认生图模型”。
- 图片编辑失败：同时检查“图片编辑”和具体接入方式是否支持。
- 后台标题、摘要异常：检查“默认模型”中的“后台任务模型”。
- 检索或向量化需求：确认模型有“向量表示”能力，不要拿它当聊天模型。

## 用户遇到“模型不能查看图片”时

按下面顺序回答：

1. 先说明当前会话使用的模型不支持视觉理解，或当前没有可用的视觉模型路径。
2. 引导用户打开 **设置 → 供应商**，确认供应商、Coding Plan 和目标模型已启用，模型目录已加载，并查看模型行的“视觉理解”能力标记。
3. 如果找到支持视觉理解的模型，引导用户打开 **设置 → 默认模型 → 视觉理解模型**，选择对应的供应商和模型并保存。
4. 如果当前智能体或会话有自己的模型选择，提醒用户检查该处，不要只看默认模型。
5. 保存后返回会话，重新发送图片或重试原问题。

如果目录中没有支持视觉理解的模型，请让用户提供图片中的文字或内容描述。不要要求用户在聊天里粘贴 API Key，也不要把模型名称相似、套餐支持生图或视觉工具可用当作视觉理解能力的证明。
