# 主动跟进与定时任务

## 主动跟进是什么

主动跟进会在一段单人聊天安静下来后，判断是否还有值得提醒、补充或继续推进的内容。如果确实有价值，原来的智能体会回到原来的聊天中主动发一条消息。

入口：设置 → 常规 → 主动跟进。它是一个对当前用户生效的总开关，默认关闭；修改后立即保存。

当前行为：

- 只支持 Nexus 内的单人聊天。
- 使用原来的智能体、原来的会话和原来的上下文。
- 发出的消息会像普通智能体消息一样出现，并带有“主动跟进”标记。
- 用户发送新消息后，尚未发出的这次跟进会取消，避免和用户的新要求冲突。
- 关闭开关只会阻止未来的跟进，不会删除已经发出的消息。

系统会自己管理安静时间、发送时段和频率，当前没有让用户设置精确时间、手动“立即跟进”或查看跟进记录的独立页面。

主动跟进只负责发消息，不会在后台使用工具、连接器、文件、临时子任务、Goal、工作图或定时任务。如果判断必须执行这些操作才能提供有价值的结果，这次应保持安静。

当前不支持多人房间和外部聊天软件。房间的群主自动接管也不是主动跟进。

## 定时任务是什么

定时任务会按照用户明确设置的时间自动运行一项工作。它不只针对移动端；网页端和桌面端都可以管理，保存后不需要一直停留在创建页面。

入口：左侧“定时任务”。这里可以从建议开始，也可以自定义任务。

创建时需要决定四件事：

1. 做什么：写清每次运行要完成的工作。
2. 什么时候做：一次、按星期、按月、每隔一段时间，或使用更灵活的计划表达式；同时选择时区，必要时设置到期时间。
3. 由谁执行：选择智能体，或者选择多人房间中的成员。
4. 结果放哪里：只保留运行记录，或送到真实存在的单人聊天、多人房间或已经配对的外部聊天。

## 选择执行上下文

创建任务时可以选择工作发生在哪种上下文中：

- 主会话：继续使用智能体的主要聊天上下文。
- 已有会话：在指定的现有聊天中运行。
- 临时独立会话：每次在较干净的上下文中执行，适合不希望长期积累内容的周期任务。
- 专用长期会话：为这项任务保留一段可持续积累的独立上下文。

如果用户不确定，优先解释每种方式是否会沿用过去内容，再让用户选择；不要只给内部名称。可用方式会随执行目标变化：多人房间任务使用已有的房间会话；使用智能体主会话执行时，当前不支持再额外把结果发送到另一个位置。

## 权限和送达

- 创建时，任务会保存当时的执行权限和工具允许范围。以后修改智能体默认配置，不会悄悄改掉已经创建的任务。
- 执行者和替它发送结果的智能体可以是两个不同设置，系统会分别保存并在运行或重试时检查。
- 来源聊天只用来说明任务从哪里创建，不自动决定执行权限或结果送达位置。
- 送到外部聊天前，消息通道必须可用，而且目标人或群已经与正确的智能体完成配对。
- 任务需要长期保留某项权限时，可能进入等待确认状态。用户应在任务页或结果接收会话中处理确认。

如果任务引用的某一段会话被删除，任务会保留但可能停止，并提示重新选择执行或接收位置。修复所有失效位置后才能重新启用。删除整个智能体或房间时，相关任务可能一起删除，操作前要特别说明影响。

## 查看和处理运行结果

定时任务页会区分需要处理、正在运行、已安排和已停止的任务。每张任务卡会显示当前计划和下次运行时间，并提供适用的操作：

- 立即运行一次。
- 启用或停用。
- 编辑或删除。
- 查看运行历史、诊断信息和生成的文件。
- 在失败后重试运行、重试发送结果，或按界面提示恢复。

“立即运行”不会改变原来的周期计划。重试发送结果时，系统会使用当前任务最新确认的接收位置。

旧版本创建的“脚本任务”仍可能出现在列表中。它们可以启停、立即运行、查看记录或删除，但当前已经不再提供新建和编辑入口。

## 怎么选择

| 需求 | 使用 |
| --- | --- |
| 希望系统在合适的时候提醒一段未完单聊 | 主动跟进 |
| 每天、每周或在指定时间自动做一件事 | 定时任务 |
| 到某个时间只提醒自己一句话 | 定时任务，并把任务内容写成提醒 |
| 用户一发消息就决定谁回应 | 单聊选择智能体，或房间的 `@` 与群主接管 |
| 持续推进一个明确结果，但不要求固定时间 | Goal |
