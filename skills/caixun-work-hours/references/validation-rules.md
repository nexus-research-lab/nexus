# RichPMS 日报校验规则速查（错误码 → 原因 → 自纠错方向）

提交走与 PMS 网页端完全相同的后端校验链，以下错误按 code 识别：

| code | 含义 | 自纠错方向 |
|---|---|---|
| 1005 | 当日工时合计不等于 8 小时 | 检查各行 hours 合计（含已锁定的审批中行原值），调整至恰好 8 |
| 1007 | 必填字段缺失 | 每行必须有 projectCode、taskId、hours、workContent |
| 1009 | 预警阻断（CRITICAL 项目） | 该项目已被管理端阻断报工，向用户说明并剔除该项目 |
| 1010 | 填报通道关闭（逾期） | 该日期已超补报窗口，引导用户联系 PMO |
| 1011 | 日期格式错误 | 使用 yyyy-MM-dd |
| 403 | scope/权限不足 | token 未含 report:write 或用户权限被回收，提示重新授权 |
| 429 | AI 通道限流 | 等待冷却（5 分钟）后继续，勿重试轰炸 |

## 日期窗口规则

- 休息日（周末/法定节假日）禁填，调休补班日（isMakeupWorkday）可填
- 项目类工时：仅可填过去及未来 30 天内（`workhour.project_future_limit_days`）
- 雇佣窗口：仅可填 [入职日, 离职日] 闭区间内的日期
- 全月纯请假会被拦截（当月最后剩余可提交日时）

## 可报项目口径（三层开关全开才可报）

项目 canReport=Y 且非结项/终止 → 员工为项目当前成员 → 任务 canReport=Y → 员工为任务当前成员。
以 `get_fillable_projects_tasks` 返回为准，不要自行推断。
