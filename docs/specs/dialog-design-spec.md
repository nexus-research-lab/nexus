# Web 弹窗设计规范

本文记录 Nexus Web 当前弹窗的结构、文案与审计合同。业务弹窗必须复用共享 modality；设计差异只来自任务类型，不来自各功能自行添加装饰层级。

## 设计语法

### 决策框

- 只保留短标题、具体后果和动作。
- 不自动补“请确认”“立即生效”“不可恢复”等泛化套话；确有不可逆后果时由业务正文明确说明。
- 不使用警告图标、消息卡或重复副标题表达危险等级，危险性由文案和确认按钮 tone 表达。

### 连接、授权与紧凑表单

- 使用 `UiDialogHeader/Footer appearance="plain"`，标题直接命名目标。
- 首屏只放当前步骤需要的字段、状态和动作；平台教程默认折叠或链接到文档。
- 凭据、二维码和验证码可以使用一个功能性承载面，但不得再嵌套状态卡、隐私宣言或装饰性图标。
- 具体业务错误可以显示；“服务内部错误”等无行动价值的占位消息必须替换为当前操作的短兜底文案。

### 选择器与工作台

- 少量互斥选项使用紧凑列表或分段控制；不为每个选项重复同一段解释。
- 目录型选择器使用普通标题、搜索/筛选和扁平行；不得用装饰图标、副标题、标签胶囊与重复按钮把每个选项包装成卡片。
- 需要持续浏览、对照或编辑的内容使用工作台布局，不在小弹窗里堆叠标题、教程、表单、画布和双重 footer。
- 桌面可使用双栏；窄屏必须切换为单栏或标签，不允许横向溢出。

### 预览器

- 文件预览只显示文件名；“图片预览”“文本预览”等可从内容判断的类型不重复显示。
- 纯画布预览可不显示标题栏，但必须保留视觉隐藏的可访问名称和独立关闭动作。

### 管理目录与历史

- 管理目录首屏只显示对象身份、必要状态和动作；实现原理、适配器教程和内部 ID 不逐项铺开。
- 来源、运行和权限的技术身份进入按需展开的诊断区；真实业务错误保持可见。
- 对象名可以直接作为弹窗标题，“当前状态”“运行历史”“需要处理”等泛化标签不与对象名、副标题和状态图标重复堆叠。
- 二次确认复用共享决策框，不调用浏览器原生 `alert`、`confirm` 或 `prompt`。

## 可访问性与行为

- `UiDialogBackdrop` 统一提供焦点陷阱、Escape、背景滚动锁和可访问命名；业务层不得复制 modality。
- 关闭、取消业务操作和提交必须保持不同语义。关闭不能暗中提交或撤销，业务取消必须调用原有控制动作。
- 异步状态原位替换当前动作或显示一行短状态，不新增重复弹窗。

## 审计状态（non-normative）

公共决策框、WorkGraph、Connector、Channel、Agent/Provider/Room 创建编辑表单、Composer 选择器、附件/Mermaid 预览、Skill/Scheduled 管理弹窗、配对、MCP、引导中心、Goal、联系人、CC Switch、Provider 初始化向导，以及历史、移动端会话切换、模型选择、记忆说明和图标选择浮层均纳入同一设计语法。后续新增入口继续按上述合同审计；本段只记录推进状态，不改变完成标准。
