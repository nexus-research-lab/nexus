## 已落地

- 先统一实现和所有权，再调整共享视觉。路由合同、通用 React/browser 能力、认证
  身份投影不再依赖 App；Markdown 通过中立能力注入接收文件动作，业务 mention/
  Slash 与 Agent scope 留在业务层；受控会话标签只处理展示和滚动，Room 命令归导航功能。
- Select 单选/多选触发器、Dialog 关闭、标签关闭复用唯一原语；登录页使用公共表单、
  按钮、排版和恢复提示。旧迁移路径与兼容转发已移除。
- 浮层只在当前模态范围内逐层退出；嵌套 Portal、禁用选择器、菜单初始焦点、隐藏
  Mention 的键盘监听均有回归测试。移动端会话切换器接入共享模态行为。
- 公共 Button 的默认高度、字重、图文间距和不可用/忙碌/hover 状态归共享样式所有者；
  Form/Select 的默认字号、行高和字段高度对齐，Select 标签不再覆盖加粗。
- TypeScript AST 依赖门禁不再保留反向依赖白名单；L3 合同检查递归覆盖已治理目录，本批扩展到 List 与 Workspace Catalog。
  业务层 13 个原生按钮几何所有者、17 处原生节点只在工程规范登记，门禁同时检测
  JSX 与直接 `createElement`。这不是允许继续复制按钮的额度。
- 对本次新增生产模块的 23 个导出符号做编译器引用审计，均有外部引用；新文件没有
  留下无调用者的兼容入口。此结论不冒充整个仓库所有导出的清理结果。
- Windows 原生浅色主题增加逐个语义 Brush 与阴影颜色的 token 投影门禁；原生主题
  变更也会触发前端 CI，避免手工维护的颜色与 Web 真相源分叉。
- 初次全前端编译器扫描覆盖 1,273 个模块、3,830 个导出，核对完全无引用运行时候选的
  动态测试用途后，移除 15 个未使用运行时导出及其失效状态；引导页 Note 迁入公共 Notice
  后再删除其样式入口，共清理 16 个运行时导出与 3 个孤立类型。类型合同与动态加载的纯模型测试入口不能
  仅因静态外部引用为零而删除，扫描结果不等于所有候选都是死代码。
- 从 Web、三个桌面入口和开发 Gallery 做模块可达性追踪（含静态、动态和类型导入），
  剩余两个独立文件分别是 Vitest setup 与用户原有未跟踪的 `lib/room-events.ts`；
  前者由测试配置加载，后者保留用户工作区状态。未发现本次提交新增的孤立生产模块。
- Contacts 与 Skill 的整卡点击层归 `WorkspaceCatalogCard.primaryAction`；共享局部
  堆叠使静态内容透传命中，次动作仍独立。ListAction 删除自身按钮 DOM 与重复状态
  配方，组合 IconButton，并统一侧栏、固定项和 Provider 条目的 hover/focus 展示。
- Select 的紧凑筛选与大号表单通过 `size` 选择；普通按钮与选择器的局部颜色、hover、
  字重、阴影覆盖已收口。新增 AST 门禁覆盖导入别名、命名空间、常量作用域、展开
  Props 和静态内联样式，当前无违规白名单；运行时或外部 CSS 仍需人工审查。
- 表单门禁扩展到 Input/Textarea/NativeSelect/SearchInput/Checkbox/Choice，包括搜索
  内部输入；移除普通字段的局部圆角、字重、行高，路径/命令/源码模板与验证码
  由共享 `textRole` 表达差异。角色只拥有展示，不猜测业务格式或修改原生输入值。
- ListRow 将侧栏和加载骨架的响应式尺寸、连续/独立边界和弱化展示收口为语义属性；
  静态/禁用行不再显示 hover。飞书连接入口使用真正的 disabled 状态保留行的名称
  和按钮语义并阻止重复命令。原生 Button/Select 检查共用 AST，识别 React 工厂别名，
  不把注释和源码示例中的标签当作实际 DOM。
- Agent 高级授权行复用 ListRow、图标框和 Typography；仅开关触发命令，已选的
  失联 Connector 仍可撤销。Skill 卡片使用 Catalog 的 dense 密度，锁定与提交中
  状态保持原边界。目录创建入口删除独立按钮实现，复用 Button 的焦点与禁用状态。
- Composer 附件的图片/文本预览和移除共三个原生按钮迁入共享 Button；保留 48px
  缩略图几何，移除统一使用 micro IconButton。Chip、Composer 与消息编辑器删除
  重复圆角和无效历史 class，只由共享输入壳/Chip recipe 持有表面。
- 四档控件与四档表面圆角集中为 token，Input/Chip/Popover/Dialog/Tooltip 等 recipe
  和内容别名统一消费。修复 Tour 缺失圆角及 Memory、Loop、目录侧面、附件文字等
  未定义颜色引用，直接选择现有语义，不新增兼容别名。
- 新 token 门禁使用 CSS parser 与 TypeScript AST 检查静态引用、模板 CSS、注释、
  字符串内容和嵌套 fallback，并逐主题检查 canonical 别名缺失、循环与块内重复。
  运行时表达式、DOM 继承和属性类型仍需实际 Surface 审查，声明集合不能代替渲染。

## 验证边界与后续迁移

- GitHub Actions 已配置同一套门禁和证据归档；本次只做本地提交，没有推送或运行远端 CI。
- Chromium/WebKit 覆盖 Web 渲染和输入行为；macOS/Windows 原生窗口 chrome、安全区、
  宿主可见性生命周期仍需在实际 App 上复查，不把浏览器结果称为原生宿主验收。
- 本轮原生检查受环境限制：Mac 锁定使 App 操作无法开始，已请求解锁；本机 Command
  Line Tools 缺少 XCTest，窗口指标测试编译失败（`no such module 'XCTest'`），生产
  Swift 编译通过。当前主机没有 Windows/.NET 环境，未执行 WPF/WebView2 测试。
- 本地字体用于 App chrome 验收，远端聊天中文字体被显式阻断；没有建立跨平台像素基线，
  也没有声称所有业务页面和全部阅读 Surface 均已视觉验收。
- `hooks/store/types/lib` 的剩余目录整理继续按领域切片渐进迁移；当前严格依赖门禁与
  公共所有者合同已经生效，不能因目录尚未整体移动而恢复反向依赖或私有普通控件。
- 工作区原有欢迎页、中文文案、探索文档与其他非本任务改动保留未提交状态。
