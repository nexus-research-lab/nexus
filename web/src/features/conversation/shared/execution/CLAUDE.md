# Execution WorkGraph

- `use-execution-resource.ts` 只读取 `GET /executions/latest` 返回的 managed `ExecutionView`，以 owner/session-scoped `execution_invalidated` WebSocket 事件合并刷新，不得再用 message/round/Goal 活动猜测图变化；后端在 mutation 后和每次 bind/rebind 后发送 invalidation fence，使断线期间从“无图”变成“有图”也能恢复，因此前端断线期间不得用 HTTP 定时轮询掩盖实时链路故障。后端返回 `null` 表示当前 session 从未产生 managed WorkGraph，runtime-only Graph 不属于这个公共资源；读取失败而保留旧快照时显式暴露 stale/last-successful-at，不派生第二套状态机。
- `execution-process-panel.tsx` 是 Composer 上方的实时 Agent Dock：只有 `plan_execution` 成功持久化 active Plan 和非空 Work Items 后才显示；它只展示去重后的一级 Agent 责任节点，以轻量连线保留协作链路感知，工作图入口固定在右侧；Agent 节点外框固定为与展开聊天消息头像一致的 32px，Dock 只在其外保留紧凑点击热区和状态环；绿色只表示该 Agent 正在运行。点击带精确 `agent_round_id` 的头像跳转到对应消息轮次，图标按钮打开右侧完整工作图。这里不得复制 DAG，也不得混入 Tool、Gate 或 Subagent。
- `execution-workgraph-surface.tsx` 是 Header “工作图”入口对应的完整辅助 Surface；桌面 Header 与移动端菜单的工作图入口都固定常驻，资源保留最近一次 terminal managed WorkGraph，直到同一 session 创建新的 managed WorkGraph 才替换，普通 runtime-only round 不得覆盖或冒充图内容；从未创建托管图时打开同一 Surface 的明确空态。Surface 顶栏默认只展示标题，`active` 不追加元信息，`waiting|paused|terminal` 仅追加一个生命周期徽标；partial/stale/error 仍作为投影可信度警告保留。Plan revision、验收进度、completion blockers 与节点 `x/N` 留在读模型、详情或画布导航中，不常驻标题栏。Composer Dock 仍以非终态 managed 图判定显示。Surface 与缩略入口消费 `room-surface-shell.tsx` 中同一个 `ExecutionResource` 和同一组 Task runs，不得自行轮询、复制状态机或制造第二份图快照。
- `execution-node-avatar.tsx` 是 Agent Dock 与完整节点图共用的 Agent/Subagent/未分配节点原语；完整图投影生命周期，Dock 投影实时活动，二者不得复用绿色表达不同状态。Subagent 使用 child runtime identity 的稳定头像，不借用父 Work Item owner 头像。Tool 图标由 `execution-tool-visual.ts` 按搜索、抓取、本地检查、浏览器、命令/代码、写入/编辑、消息、生成、工作流控制与外部 capability 区分，状态仍只由边框和角标颜色表达，禁止让所有动作退化为同一扳手或另造一套状态色。
- `execution-process-model.ts` 只投影公共 managed `ExecutionView` 的标签、当前节点、一级 Agent 去重、Lead/coordination 优先顺序、稳定头像 identity 与运行图可见性。无 Plan 的 runtime-only Agent Loop 只属于后端内部运行事实/诊断面，不进入 `GET /executions/latest`，不得填充固定的 Header/移动端 Surface、触发 Composer Dock，或冒充 managed Execution、Assignment 或 Goal。`coordination` 只表达 Lead 对已声明根工作项的责任，禁止冒充已经发生的 dispatch；`parent_work_item_id` 是 containment，禁止进入 readiness 或布局边。
- `execution-node-task-model.ts` 只允许以 WorkAttempt 的 `executor_agent_id + agent_round_id` 精确关联 Conversation Task run；缺失或不匹配时不展示，禁止按 Agent、消息位置或时间猜测节点归属。
- `execution-node-task-list.tsx` 只把命中的 runtime-local Task 作为节点局部步骤展示，不把 Task 状态提升为 Work Item、Submission 或 Acceptance。
- `execution-workgraph-layout.ts` 保持主责任图自上而下的依赖/dispatch 层级；同一 Agent 的可见 Tool/Subagent 按结构化父身份形成真正的自上而下 ownership tree：同一拥有者的直接子节点按稳定顺序从左向右，每个 Subagent 子树预留独立横向车道，后代不得再按全局层重新居中而偏离真实父节点。只为一级 Agent/Gate 的完整 runtime tree 绘制一个外框，Subagent 不再生成套娃子图框，其 exact ownership 只由向下树线和独立车道表达。后端显式边优先，历史快照仅在可见节点已有 `parent_node_id`、同一 `agent_round_id` 或唯一同责任 Agent 时补出 invoke/spawn 方向边，禁止留下孤点或从文字猜关系。所有方向边使用纯 `M/L` 正交折线，禁止在密集节点间使用贝塞尔曲线；未配对的 invoke/spawn 可保留短虚线，exact `loop_back` 继续和正向边保持成对语义。向上回连必须像正常流程一样先从子节点底部垂直离开当前节点层，再沿所属子图圆角框内预留的底部与左右走廊形成 U 形轨道，左右侧轨和底部总线必须固定内缩于圆角边框的安全槽，保留稳定可见的留白，最后水平进入父节点侧口；禁止为了走捷径横穿 ownership fan 或越出子图框。回连路由只把穿过无关节点视为硬冲突，不把线与线重叠视为冲突；同一子图、目标与侧面的回连应在各自短接入段后合流到同一条 U 形总线和箭头端口，像普通流程图一样减少视觉线数。普通流程使用可读中性灰，回连使用降饱和暖色和接近的线宽/透明度，不得再靠“一条几乎不可见、一条高饱和”表达关系。`retry` 只表达 Agent 已明确选择并精确关联的再次执行；控制边不参与父级或深度推断，并禁止穿过头像或整排运行节点。托管 WorkGraph 只接收已绑定 Work/Review/Coordination lane 的 runtime Agent，普通 Room reply root 留在 Conversation activity。
- 每个 durable Tool NodeRun 永远对应独立画布节点，失败与随后成功不得折叠成 `×N` 聚合节点；只有 runtime 明确提供 `retry_of_*` 身份时才在两个节点之间增加 retry 边。没有 exact retry 事实时不得按同名、参数或时间邻近猜边，但同一直接 owner 下同类工具在失败后出现的最后一个成功 Run 必须提升到画布，使用户同时看到失败与恢复事实。
- WorkGraph 与模型运行上下文使用不同读取边界：后者继续使用有界 Snapshot，前者必须读取当前 Plan 的完整 durable child Attempt 历史，因此同一 parent 下每次真实 Subagent launch 都是独立节点。旧执行只允许用 exact `tool_use_id` 把受限 task 历史恢复到对应 Attempt；Agent launch Tool 只提供关联与边证据，不得覆盖 Subagent 自身状态、task identity、头像身份或结果。
- `execution-workgraph-interaction-model.ts` 与 `execution-workgraph-controls.tsx` 只维护当前用户的折叠、全文搜索、缩放、适配和当前节点定位，并统一计算有界比例、指针焦点锚点与随 viewport 变化的对称平移留白；搜索会展开命中节点的祖先，折叠只向 layout 传递隐藏集合，禁止修改权威拓扑、运行状态或 Agent 路线。
- `execution-workgraph-canvas.tsx` 观察自身容器并负责低对比度工作板网格、全边界可达的白板 viewport、无文字子图轮廓、整条线鼠标命中区与边中点原生键盘按钮，以及贴近所选节点或边、自动避让左右边界且不随画布比例缩小的屏幕尺寸悬浮检查器。白板网格本身是唯一的主图背景，承载 layout 坐标的内部容器不得再绘制圆角、边框或底色；只有表达真实归属的子图框可以保留轮廓。节点与边检查器必须使用高不透明 `surface-popover-*` 阅读面，正文滚动区和 sticky header 共用同一实体背景，禁止让网格、节点或连线透过长文本。空白左键、空格加左键、中键或右键拖拽均可平移；触控板双指滚动保留二维平移，Ctrl/Command 加滚轮、触控捏合与空白双击围绕当前指针缩放，工具条和键盘缩放围绕视口中心，适配与节点定位显式居中且不得跳动焦点。普通节点、边、控件和检查器内容不得误触平移；空白轻点或 Escape 关闭节点或边检查器，真实拖拽只移动视口且不得误关详情。边检查器只解释来源、目标、exact Run identity、观测时间与已发生语义，不提供路线 mutation。`execution-node-run-history.tsx` 在节点检查器内展示每次 NodeRun 的结果/错误、耗时与 exact structured Artifact，并只把安全的 workspace 相对路径交给既有 Workspace 打开链路。每个 exact child Tool Run 都先按 durable parent identity 归入直接 Agent/Subagent owner；外部搜索/抓取、第三方 capability 调用、浏览器操作、命令或代码执行及文件写入/编辑等用户可观察动作进入画布，普通成功的本地读取/查找、filesystem/workspace MCP、工具发现/Skill 加载及已被 Work Item/Gate/Subagent 完整表达的编排调用保持 `detail` 并列在该 owner 的检查器中。运行中或失败/中断/取消、参与控制边、带 Artifact 或携带通用 `workgraph_visibility` 提示仍可按结构事实提升可见性；仅有 provider progress、没有独立 start/finish 身份的记录不得成为节点。
- 后端必须先完成 runtime visibility 投影，再对 `visibility != detail` 的主图节点和连接主图节点的边应用独立窗口；普通成功读取/查找等 `detail` 历史不占主图配额，也不触发 partial。只有本应进入主图的节点或边确实被截断时才返回 `runtime_*_total` 与 `runtime_*_truncated` 并由 Surface 显式显示 partial；读取失败但仍保留最后成功快照时显式显示 stale，禁止把截断、断线或旧数据伪装成完整实时图。
- 节点检查器以结构化 owner 为责任人真相源；自由文本 objective 若以同一 owner 身份开头，只在展示层消除这段冗余前缀，不改写后端 Work Item。
- Composer 上方入口不承载交付契约工作台；完整领域数据仍由后端 read model 保留，节点进度只回答当前任务、走到哪里、由谁负责。
- UI 不提供状态写入按钮；编排 mutation 仍由模型语义工具和后端 authority fence 负责，详情中的失败与回连不得被解释成服务端自动重试或固定路由。
