# Execution WorkGraph

- `use-execution-resource.ts` 只读取 `GET /executions/latest` 返回的 managed `ExecutionView`，以 owner/session-scoped `execution_invalidated` WebSocket 事件合并刷新，不得再用 message/round/Goal 活动猜测图变化；后端在 mutation 后和每次 bind/rebind 后发送 invalidation fence，使断线期间从“无图”变成“有图”也能恢复，因此前端断线期间不得用 HTTP 定时轮询掩盖实时链路故障。后端返回 `null` 表示当前 session 从未产生 managed WorkGraph，runtime-only Graph 不属于这个公共资源；读取失败而保留旧快照时显式暴露 stale/last-successful-at，不派生第二套状态机。`use-workgraph-history-resource.ts` 只在 Surface 历史下拉打开或已切换历史图时读取 exact session 的 managed 历史；历史快照、选择、加载状态和迟到响应必须绑定 exact session，切换 session 立即清空，只有同 session 的读取失败可以保留 stale 历史并显示安全重载动作；不得读取沉淀库，也不得反向覆盖最新图资源。
- `execution-process-panel.tsx` 是 Composer 上方的实时 Agent Dock：只有 `plan_execution` 成功持久化 active Plan 和非空 Work Items 后才显示；它只展示去重后的一级 Agent 责任节点，以轻量连线保留协作链路感知，工作图入口固定在右侧；Agent 节点外框使用 24px 紧凑基线，整个 Dock 与 Room 协作和 Task 状态共用 32px 可见高度、12px 字体和细线图标，状态环不得把外框撑高；绿色只表示该 Agent 正在运行。点击带精确 `agent_round_id` 的头像跳转到对应消息轮次，图标按钮打开右侧完整工作图。这里不得复制 DAG，也不得混入 Tool、Gate 或 Subagent。
- `execution-workgraph-surface.tsx` 是 Header “工作图”入口对应的完整辅助 Surface；桌面 Header 与移动端菜单的工作图入口都固定常驻，资源保留最近一次 terminal managed WorkGraph，直到同一 session 创建新的 managed WorkGraph 才替换，普通 runtime-only round 不得覆盖或冒充图内容；从未创建托管图时打开同一 Surface 的明确空态。顶栏不显示冗余的 WorkGraph 前导图标，只保留标题旁与 Session 历史同构的独立向下箭头；标题与历史组成左侧上下文组，生命周期与保存动作组成右侧动作组，右侧 WorkGraph 区域不承载已保存目录。exact 图完成后，生命周期徽标旁显示“保存为草图”：HTTP 请求默认对话模型从完整实际图生成或复用按 exact source Execution 去重的 durable Draft，除 Slash 与 logical key 外的面向用户字段跟随界面语言；`workgraph-distillation-dialog.tsx` 允许直接修订命令名、标题和描述，并可打开 `workgraph-metadata-editor-dialog.tsx`。编辑统一由 owner 的 Nexus 主智能体在目录隐藏专用 DM 中承载，不继承来源 DM/Room transcript、Connector 或权限；关闭 UI 不删除会话，再次打开恢复同一对话。左侧 `DmChatPanel` 展示本地接待说明和该隐藏会话自身的编辑消息，Composer 羽化底色与左侧编辑面共用同一 token。非运行态草图与命名图统一由 `workgraph-workflow-canvas-preview.tsx` 经 `workgraph-workflow-canvas-model.ts` 投影成中性 `ExecutionView`，再完整复用 Room/DM 的 `ExecutionWorkGraphCanvas`；确认对话框与能力详情必须消费该同一预览 Surface，只允许外层尺寸变化，承载画布的直接父级保持 flex 高度。该预览 Surface 使用摘要节点密度，直接显示节点标题、两行工作目标以及 required/terminal 关键标记，点击仍打开完整交付、验收与运行详情；实时运行图继续默认使用图标密度。编辑 Session 不挂载 MCP，只开放 `execution-orchestrator` Skill、完整草图 `revise_workgraph_preview` 与不可变版本 `select_workgraph_preview_revision`；每次修改追加版本，head revision 用于 CAS，selected revision 表达用户偏好，选择旧版不删除新版。版本行属于动态单选集合，必须用 `UiChoiceButton` 保留逐项禁用、胶囊版本语义和横向滚动，不得手写选择按钮的边框、色彩或字重。服务端校验 logical key、节点 kind、父子结构、DAG、key 主路径和 terminal 交付；应用只把所选版本投影回当前 Draft UI，不改写源 Execution 或源聊天。`named-workgraph-sketch.tsx` 只保留目录卡片与消息卡片的紧凑预览。确认后前端调用 preview save 调度 API，宿主在独立目录隐藏内部 DM Session 启动 `HiddenFromUser + Synthetic` round；该 Session 不继承或续写源 transcript，pending、过程、工具与完成事件全程隐藏，真正持久化只由 `execution-orchestrator` 调用 exact `distill_workgraph` CLI。“工作图”在能力侧栏与 Loop 同级，并在 Composer 能力菜单查看和复用已保存草图。Surface 顶栏默认只展示标题，partial/stale/error 仍显式呈现；Composer Dock 仍只由非终态 managed 图驱动。Surface 与缩略入口消费同一个 `ExecutionResource`，不得自行制造第二份图快照。
- 普通 DM/Room 的 WorkGraph authoring typed result 会持久化 `workgraph_artifact` 完整快照并只把同轮最后一张图提升到 final surface。`workgraph-artifact-block.tsx` 默认展示当前草图/已保存图的紧凑卡片；“与来源图对照”才通过 exact `GET /executions/{execution_id}?session_key=...` 加载来源画布，桌面双栏、窄屏切换。历史卡片必须固定为消息当时版本，不能读取当前 Draft head 替换；来源失败时仍保留草图并提供重试。
- WorkGraph 初次保存确认固定为左侧命名表单、右侧低文字结构预览，不显示模型或后台实现状态；来源对照弹窗不设外层说明标题，双栏各自只保留名称与版本/来源标记。编辑 DM 的本地接待说明只用一段短句交代修改方式和版本事实，不展示示例清单或重复操作教程。
- `execution-node-avatar.tsx` 是 Agent Dock 与完整节点图共用的 Agent/Subagent/未分配节点原语；完整图投影生命周期，Dock 投影实时活动，二者不得复用绿色表达不同状态。Subagent 使用 child runtime identity 的稳定头像，不借用父 Work Item owner 头像。Tool 图标由 `execution-tool-visual.ts` 按搜索、抓取、本地检查、浏览器、命令/代码、写入/编辑、消息、生成、工作流控制与外部 capability 区分，状态仍只由边框和角标颜色表达，禁止让所有动作退化为同一扳手或另造一套状态色。
- `execution-process-model.ts` 只投影公共 managed `ExecutionView` 的标签、当前节点、一级 Agent 去重、Lead/coordination 优先顺序、稳定头像 identity 与运行图可见性。无 Plan 的 runtime-only Agent Loop 只属于后端内部运行事实/诊断面，不进入 `GET /executions/latest`，不得填充固定的 Header/移动端 Surface、触发 Composer Dock，或冒充 managed Execution、Assignment 或 Goal。`coordination` 只表达 Lead 对已声明根工作项的责任，禁止冒充已经发生的 dispatch；`parent_work_item_id` 是 containment，禁止进入 readiness 或布局边。
- `execution-node-task-model.ts` 只允许以 WorkAttempt 的 `executor_agent_id + agent_round_id` 精确关联 Conversation Task run；缺失或不匹配时不展示，禁止按 Agent、消息位置或时间猜测节点归属。
- `execution-node-task-list.tsx` 只把命中的 runtime-local Task 作为节点局部步骤展示，不把 Task 状态提升为 Work Item、Submission 或 Acceptance。
- `execution-workgraph-layout.ts` 保持主责任图自上而下的依赖/dispatch 层级；同一 Agent 的可见 Tool/Subagent 按结构化父身份形成真正的自上而下 ownership tree：同一拥有者的直接子节点按稳定顺序从左向右，每个 Subagent 子树预留独立横向车道，后代不得再按全局层重新居中而偏离真实父节点。主责任层只在确定减少边交叉时执行稳定的重心排序，交叉数相同时必须保留原位置顺序，避免实时更新造成无意义换位。只为一级 Agent/Gate 的完整 runtime tree 绘制一个外框，Subagent 不再生成套娃子图框，其 exact ownership 只由向下树线和独立车道表达。后端显式边优先，历史快照仅在可见节点已有 `parent_node_id`、同一 `agent_round_id` 或唯一同责任 Agent 时补出 invoke/spawn 方向边，禁止留下孤点或从文字猜关系。所有方向边使用纯 `M/L` 正交折线，禁止在密集节点间使用贝塞尔曲线；子图内部的普通正向边固定从来源底部端口进入目标顶部端口，并按每个层间走廊分配稳定轨道，不同来源与目标的边不得因共享几何中线而伪装成同一关系，只有同一语义类别下 exact 同源 fan-out 或同目标 fan-in 才能合流为局部总线并绘制真实分叉点。跨子图普通边不得再穿入展开子图连接核心节点，而应按方向连接子图上、下或侧边框的代理端口；端口按 edge 类别、角色和 exact endpoint 稳定分槽，同一 exact endpoint 可复用端口，底层 source/target 真相不得改写，并保留只在路径聚焦时展示的端口到真实节点正交短引线。每个子图边框连同外侧安全间距都是其他跨子图流程边的硬障碍，路由必须通过稳定的正交可见走廊绕开，禁止贴边重叠或穿过不属于该边的子图内部。未配对的 invoke/spawn 可保留短虚线，exact `loop_back` 继续和正向边保持成对语义。向上回连必须像正常流程一样先从子节点底部垂直离开当前节点层，再沿所属子图圆角框内预留的底部与左右走廊形成 U 形轨道，左右侧轨和底部总线必须固定内缩于圆角边框的安全槽，保留稳定可见的留白，最后水平进入父节点侧口；禁止为了走捷径横穿 ownership fan 或越出子图框。回连路由只把穿过无关节点视为硬冲突，不把线与线重叠视为冲突；同一子图、目标与侧面的回连应在各自短接入段后合流到同一条 U 形总线和箭头端口，像普通流程图一样减少视觉线数。普通流程使用可读中性灰，回连使用降饱和暖色和接近的线宽/透明度，不得再靠“一条几乎不可见、一条高饱和”表达关系。`retry` 只表达 Agent 已明确选择并精确关联的再次执行；控制边不参与父级或深度推断，并禁止穿过头像或整排运行节点。托管 WorkGraph 只接收已绑定 Work/Review/Coordination lane 的 runtime Agent，普通 Room reply root 留在 Conversation activity。
- execution-workgraph-controls.tsx 只能组合共享 UiButton / UiIconButton、语义 Popover Surface 与 App Typography；节点卡、边命中区和折叠计数因自身表达图形几何可由 Canvas 持有原生 DOM，但搜索、缩放、适应、定位、展开和检查器关闭不得再私写控件状态。
- 每个 durable Tool NodeRun 永远对应独立画布节点，失败与随后成功不得折叠成 `×N` 聚合节点；只有 runtime 明确提供 `retry_of_*` 身份时才在两个节点之间增加 retry 边。没有 exact retry 事实时不得按同名、参数或时间邻近猜边，但同一直接 owner 下同类工具在失败后出现的最后一个成功 Run 必须提升到画布，使用户同时看到失败与恢复事实。
- WorkGraph 与模型运行上下文使用不同读取边界：后者继续使用有界 Snapshot，前者必须读取当前 Plan 的完整 durable child Attempt 历史，因此同一 parent 下每次真实 Subagent launch 都是独立节点。旧执行只允许用 exact `tool_use_id` 把受限 task 历史恢复到对应 Attempt；Agent launch Tool 只提供关联与边证据，不得覆盖 Subagent 自身状态、task identity、头像身份或结果。
- `execution-workgraph-interaction-model.ts` 与 `execution-workgraph-controls.tsx` 只维护当前用户的折叠、全文搜索、缩放、适配、当前节点定位和只读路径聚焦，并统一计算有界比例、指针焦点锚点与随 viewport 变化的对称平移留白；悬停或选中节点时分别沿非控制边追踪完整祖先和后代，不得把回连环扩散为整张图，exact 相邻控制边仍随路径显示。搜索会展开命中节点的祖先，折叠只向 layout 传递隐藏集合，禁止修改权威拓扑、运行状态或 Agent 路线。
- `execution-workgraph-canvas.tsx` 观察自身容器并负责低对比度工作板网格、全边界可达的白板 viewport、可整体悬停的无文字子图轮廓、跨子图边框代理端口、语义局部总线的分叉点、整条线鼠标命中区与精确路径中点原生键盘按钮，以及贴近所选节点或边、自动避让左右边界且不随画布比例缩小的屏幕尺寸悬浮检查器。悬停子图空白区域时必须突出其全部节点、内部关系、直接进出边、边界端口及相邻端点，并降低其他内容；节点级悬停、键盘聚焦或选中优先于子图悬停，并突出完整上下游路径；直接聚焦边时只保留该边和两端节点，触控用户通过点击获得同一持久状态。跨子图边的精确端点短引线默认不显示，只在该边进入聚焦路径时以弱虚线连接真实节点和边框端口，箭头与主要路径仍终止在目标边框，避免重新制造穿透子图的主视觉。紧凑画布的对角箭头固定打开共享 Dialog 承载的近全屏大图，大图不显示重复标题栏，只保留右上角悬浮关闭按钮与供无障碍命名使用的隐藏标题，并完整复用搜索、缩放、适应、定位、折叠、聚焦、检查器和 workspace 文件动作；适应视图使用独立 Scan 图标，大图内部不得递归显示第二个大图入口，关闭、焦点循环、Escape 与页面滚动锁全部复用共享模态协议。白板网格本身是唯一的主图背景，承载 layout 坐标的内部容器不得再绘制圆角、边框或底色；只有表达真实归属的子图框可以保留轮廓。节点与边检查器必须使用高不透明 `surface-popover-*` 阅读面，正文滚动区和 sticky header 共用同一实体背景，禁止让网格、节点或连线透过长文本。空白左键、空格加左键、中键或右键拖拽均可平移；触控板双指滚动保留二维平移，Ctrl/Command 加滚轮、触控捏合与空白双击围绕当前指针缩放，工具条和键盘缩放围绕视口中心，适配与节点定位显式居中且不得跳动焦点。普通节点、边、控件和检查器内容不得误触平移；空白轻点或 Escape 关闭节点或边检查器，真实拖拽只移动视口且不得误关详情。边检查器只解释来源、目标、exact Run identity、观测时间与已发生语义，不提供路线 mutation。`execution-node-run-history.tsx` 在节点检查器内展示每次 NodeRun 的结果/错误、耗时与 exact structured Artifact，并只把安全的 workspace 相对路径交给既有 Workspace 打开链路。每个 exact child Tool Run 都先按 durable parent identity 归入直接 Agent/Subagent owner；外部搜索/抓取、第三方 capability 调用、浏览器操作、普通命令或代码执行及文件写入/编辑等用户可观察动作进入画布，普通成功的本地读取/查找、filesystem/workspace MCP、工具发现/Skill 加载、已被 Work Item/Gate/Subagent 完整表达的编排调用，以及经严格单进程语法识别的 Goal/Execution CLI 控制 transport 保持 `detail` 并列在该 owner 的检查器中。控制 transport 即使失败、重试或携带 Artifact 也不得成为画布节点；其他运行中或失败/中断/取消、参与控制边、带 Artifact 或携带通用 `workgraph_visibility` 提示的真实动作仍可按结构事实提升可见性。仅有 provider progress、没有独立 start/finish 身份的记录不得成为节点。
- `execution-workgraph-layout.ts` 的目标箭头必须按最后一段的接近方向选择上、下、左或右中心锚点，并在节点描边、焦点环或子图边框端口外保留固定可见间距；不得把横向箭头终止在顶部锚点，也不得让 marker 覆盖端口圆点。
- 后端必须先完成 runtime visibility 投影，再对 `visibility != detail` 的主图节点和连接主图节点的边应用独立窗口；普通成功读取/查找等 `detail` 历史不占主图配额，也不触发 partial。只有本应进入主图的节点或边确实被截断时才返回 `runtime_*_total` 与 `runtime_*_truncated` 并由 Surface 显式显示 partial；读取失败但仍保留最后成功快照时显式显示 stale，禁止把截断、断线或旧数据伪装成完整实时图。
- 节点检查器以结构化 owner 为责任人真相源；自由文本 objective 若以同一 owner 身份开头，只在展示层消除这段冗余前缀，不改写后端 Work Item。
- Composer 上方入口不承载交付契约工作台；完整领域数据仍由后端 read model 保留，节点进度只回答当前任务、走到哪里、由谁负责。
- UI 不提供 WorkGraph 状态写入按钮；编排与命名工作图保存 mutation 仍由模型语义工具和后端 authority fence 负责。UI 可以删除独立的命名工作图 aggregate，但不能修改图边、责任、运行状态或路线；详情中的失败与回连不得被解释成服务端自动重试或固定路由。
- WorkGraph 对话编辑器必须以 Nexus 主智能体身份展示一条只存在于视图的接待说明，覆盖可修改范围、自然语言示例、版本选择和“应用”路径；不得把该说明写入隐藏 Session transcript、源 transcript 或模型上下文。该说明是首次编辑的顶部初始滚动锚点，短内容向下增长；恢复已有对话时按普通 FOLLOW/READING 规则保持位置。
- 初始草图抽取必须把完整 source logical-key 节点、父子层级和依赖交给模型，宿主标记并强制保留 required/terminal、拓扑引用、验证/复核和协作边界；模型以抽象具体任务语义为主，只有移除后不损失结构语义的非关键孤立节点才可省略。
- WorkGraph 画布加载使用共享 `lg` Spinner，常规按钮、菜单和检查状态使用 `sm/md`，版本切换使用 `xs`；三个 WorkGraph Surface 不得自行拼接旋转、颜色或 reduced-motion class。
