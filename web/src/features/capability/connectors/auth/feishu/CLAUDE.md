# Feishu Connector Auth

- 飞书云文档连接前必须先显式选择“扫码连接”或“手动配置（兜底）”，不得根据历史 App ID 自动决定路径。
- 官方扫码是主路径，飞书页面本身负责选择已有应用或创建新应用；手工路径只在扫码不可用时收集 App ID / Secret。
- `feishu-web-authorization-window.ts` 只管理取得 App ID 后的紧凑 Web 用户授权窗口；窗口先同步绘制轻量加载态，再延后一帧导航到飞书，创建、关闭和重复 URL 导航必须幂等，不得在应用二维码阶段提前出现。
- 应用选择/创建阶段允许扫码；后续用户 Device Authorization 只直接打开飞书链接，因为把该链接重新编码为二维码会在飞书内置扫一扫中持续 pending。桌面端取得最终 App ID 后通过原生宿主自动拉起该链接；Web 同样只在此时尝试弹窗，被浏览器拦截时以明确主按钮让用户一次点击继续。
- App ID / Secret 只服务于当前有效连接和 token 刷新；取消、失败或断开时必须删除，不保留为下一次连接的默认状态。
- 弹窗只持有步骤和输入草稿，网络请求、清理与反馈统一由 connector controller 负责。
- 选择页只用两行短选项区分扫码与手工配置；手工页只保留兜底提示、两个凭据字段和继续动作，不复述后续授权实现。
