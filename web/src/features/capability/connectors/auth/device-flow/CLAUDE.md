# Connector Device Flow

- `connector-device-auth-dialog.tsx` 装配 GitHub 授权码、飞书应用选择二维码或飞书用户授权链接，以及复制和跳转交互。
- `use-connector-device-auth.ts` 只负责轮询器随授权会话和飞书下一阶段切换而启停。
- `connector-device-auth-poller.ts` 独占定时器、退避、阶段切换和终态回调。

轮询器停止后不得再发出消息、错误或连接完成回调；服务端 `slow_down` 只调整下一轮间隔。飞书应用选择/创建阶段使用官方支持的二维码，且不得提前创建额外浏览器窗口；用户 Device Authorization 阶段只提供直接打开链接，不得把链接重新编码为二维码。桌面端在阶段切换后通过原生 bridge 自动打开用户授权链接；Web 端只在拿到 App ID 并进入该阶段后尝试新建授权窗口。浏览器可能拦截异步弹窗，因此 Web 失败态必须明确指向下方主按钮，两端都保留用户点击兜底。成功终态必须先关闭授权弹窗，再触发目录与详情刷新；刷新失败不得回退或清理已经成功的连接。飞书成功连接后的正常关闭保留当前应用凭据，用户取消或错误关闭必须走清理事务。

可见弹窗只显示当前状态、授权码/二维码或跳转动作，不再重复介绍 Device Flow、应用阶段或内部连接实现。
