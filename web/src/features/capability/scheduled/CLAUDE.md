# 定时任务

## 目录边界

- 根目录只保留页面装配、实时刷新和跨子域格式化。
- `controller/` 负责列表资源、写命令、并发状态和反馈。
- `history/` 负责运行记录资源、命令、弹窗壳层和分层视图。
- `board/` 负责看板状态、必要信息卡片、排序和建议空态；列名与数量已经表达空列，不再渲染重复的空态图标和句子。
- `dialog/` 负责创建与编辑表单，`pickers/` 负责时间选择。

## 约定

- 页面只加载定时任务资源，不附带 Heartbeat 或其他自动化资源。
- 实时列表由 `scheduled_task_changed` 驱动，WebSocket 连接建立或重连后补拉一次；断线期间不启动 HTTP 定时轮询。
- 写命令先提交 API 返回的权威对象，再静默刷新做服务端对账。
- Agent 通知使用任务自身的 `agent_id`，不得使用页面默认 Agent 代替。
- 运行历史请求和动作必须绑定当前 Job；切换或关闭弹窗后，旧结果不得写回。
- 看板列只投影真实调度状态，不允许拖拽制造服务端不存在的状态迁移。
- 任务卡保留可见外框，并用统一方形图标框投影当前调度状态；状态图标只辅助识别，不替代列与文本语义。
- 创建编辑、注意事项和运行历史弹窗统一使用 plain chrome；标题只显示当前动作或任务名，内部 Job/Run/Request 身份只在折叠诊断中出现。
- 删除任务和释放运行占用必须使用共享产品内决策框，文案只说明当前动作及直接后果，不暴露 Job/Run ID 或浏览器原生确认样式。
