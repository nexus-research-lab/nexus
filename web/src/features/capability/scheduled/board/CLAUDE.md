# 定时任务看板

- `scheduled-task-board.tsx` 只处理加载、错误、建议空态和四组状态装配。
- `scheduled-task-card.tsx` 负责单项必要信息、注意事项入口、权限核心动作和操作菜单，不请求 API；`deleting` 仅允许历史/刷新，`review_required` 额外允许明确确认原执行端已停止后的二次危险删除收口，其他动作必须显式禁用。时间行只表达时间，权限块只表达请求内容，禁止重复同一句状态文案，执行中身份图标只在允许动态效果时持续旋转。
- `scheduled-task-permission-actions.tsx` 是卡片与详情共用的权限动作集合；卡片使用短标签直接处理，详情保留完整标签。`scheduled-task-attention-dialog.tsx` 承载目标资源、完整工具身份和最近运行诊断；`scheduled-task-attention-model.ts` 只投影 capability 与资源摘要。
- `scheduled-task-board-model.ts` 是状态分列、权限状态投影、排序、卡片文案和建议预设的单一真相源。
- 看板状态由任务事实自动投影，不提供拖拽或人工状态迁移；历史执行结果不伪装成独立工作流阶段。
- 看板与能力标题一起铺满可用工作面，始终保持四列状态关系；宽度不足时由看板容器横向滚动，各列任务区独立纵向滚动，不折成两列。
- 无任务时的快速建议复用普通管理目录的桌面三列网格，不影响正式看板的四列结构。
- 看板空态动作统一复用 `UiButton`，标题、说明、列名和计数统一由 Typography role 管理，刷新图标统一使用 Spinner recipe；业务文件不得另写近似字号、焦点环、圆角或旋转动效。
- 卡片显示任务名称、一行指令摘要、计划、当前时间状态和单一注意事项摘要；指令摘要用于区分任务，完整指令留在编辑面。待处理权限的核心动作直接可见，目标资源、完整错误和技术字段进入注意事项详情，执行会话与投递目标继续留在编辑或历史视图。新 attempt 运行期间不展示上一段执行的旧错误，本次完成后的结果再决定是否恢复异常入口。
- 权限状态是待处理卡片与详情的主原因，即使 Request 正在刷新也不得退化成“最近运行异常”；Provider/投递错误只能作为附带诊断。审批与显式重试动作必须携带当前 Request 的 job、run 和 policy revision，缺少精确请求时不渲染动作。
- durable 删除态高于绑定、权限和旧运行错误；`deleting` 必须说明删除已受理，`review_required` 必须说明数据尚未删除、原执行是否停止无法确认且不会自动重做。人工确认必须说明继续后删除任务与历史、此前外部影响无法撤回，并使用不含任何内部 ID/token 的二次确认。两者都要说明刷新/查看历史的下一步，不展示旧权限操作或最近错误。
- 注意事项弹窗以任务名为唯一标题，正文直接显示具体绑定、权限或运行问题；不得用警告图标、任务名副标题、“当前状态”或“原内容已保留”一类状态自述卡重复表达。
